# PayRouters web

Client-side SvelteKit SPA: the admin dashboard and the public customer Snap page. It has no SSR and no
prerendering. `adapter-static` builds to `build/`, with `index.html` as the SPA fallback.

Stack: Svelte 5 (runes), SvelteKit, TypeScript, Tailwind CSS v4, shadcn-svelte (vega preset), pnpm.

## Requirements

- Node 22+
- pnpm 10 (the repo uses pnpm; `pnpm-lock.yaml` is committed)
- The PayRouters backend on `http://127.0.0.1:8080` for development

## Develop

```sh
pnpm install
pnpm dev
```

The Vite dev server proxies `/admin`, `/snap/api`, `/v1` and `/healthz` to `http://127.0.0.1:8080`, so
the app runs same-origin, as it does in production. Sign in at `/login` with the backend's `ADMIN_TOKEN`.

## Build

```sh
pnpm build      # writes build/ (index.html + assets)
pnpm preview    # serve build/ locally
```

The backend serves `build/` from `WEB_DIR`. Any path outside `/v1`, `/admin`, `/snap/api`, `/webhooks`
and `/healthz` falls back to `index.html`, so deep links such as `/snap/<token>` work.

## Checks

```sh
pnpm check      # svelte-kit sync + svelte-check (types)
pnpm lint       # prettier --check + eslint
pnpm format     # prettier --write
```

`src/lib/components/ui/` holds shadcn-svelte code generated by the CLI. It is excluded from ESLint.

## Environment

No environment variables are needed by the web build. The admin token is entered at sign-in and kept in
`localStorage` (`payrouters.admin_token`). Mode (sandbox/live) is persisted in `payrouters.mode`.

## Layout

- `src/lib/api/`: typed API client. `types.ts` mirrors `docs/api.md`. `client.ts` adds the bearer header,
  parses `{ error: { code, message } }` into `ApiError`, and sends a 401 to `/login`.
- `src/routes/(admin)/`: token-guarded dashboard (overview, payments, cash-ins, products, providers,
  webhooks, playground).
- `src/routes/(public)/snap/[token]/`: public customer payment page, polling every 3 s while pending.
- `src/lib/format.ts`: IDR (`id-ID`), Asia/Jakarta dates, date presets.
